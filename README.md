# 后台网课不断播（NoPause）— Edge / Chrome 扩展
# 项目背景为了解决学习通网课需要手动播放以及鼠标移出页面自动停止的问题，所以做了这个插件，这个插件使用deepseek v4.1flash制作，希望可以帮助到广大深受学习通水课伤害的大学生们，希望大家有更多的时间做自己想做的事情。
**当前版本：1.0.18（"1.0 超星修正版"）**

## 一、安装（开发者模式加载，约 30 秒）
1. 解压release中的压缩包
2. 打开 Edge，地址栏输入 `edge://extensions/` 回车。
3. 打开左下角的 **开发人员模式**（Developer mode）。
4. 点击 **加载解压缩的扩展**（Load unpacked）。
5. 选择本文件夹：`chaoxing-auto-extension`
   （里面必须能直接看到 `manifest.json`，不要再往里套一层目录）。
6. 工具栏出现蓝色播放按钮图标即安装成功。建议点击地址栏右侧的扩展图标 →
   把本扩展 **固定到工具栏**，方便随时开关。

> Chrome 同理：`chrome://extensions/` → 开发者模式 → 加载已解压的扩展程序。

**安装后请刷新一遍已经打开的网课页面**（F5），让脚本在新页面上生效。

## 二、怎么用

- **默认就是开启的**，装完刷新页面即可，不需要任何操作。
- 点工具栏图标可打开面板：
  - **总开关**：一键开/关。关闭后完全恢复网站原本行为。
  - **阻止网站自动暂停**：拦截网页 JS 里的 `video.pause()`。你自己点播放器上的
    暂停按钮依然有效。
  - **自动播放并保持（默认开启）**：发现暂停的视频就自动播起来——先临时静音
    （静音播放不受浏览器自动播放限制），播起来后恢复声音。**与「下一节」互不影响**，
    不开「下一节」也会一直保持播放。
  - **拦截鼠标移出检测（超星必开）**：屏蔽 `mouseout`/`mouseleave` 类事件。
    **用超星/学习通的话这一项必须开着**，它正是超星暂停视频的主要手段。
  - **阻止后台静音**：页面切到后台时，不允许网站把视频静音或把音量拉到 0。
  - **巡检抢救**：兜底方案，发现视频被暂停就自动续播（最强；如果某个直播站
    出现"暂停不了"，把它关掉）。
  - **下一节（有风险）**：视频播完后自动点"下一节/下一集"进入下一个视频；
    遇到答题页直接点"跳过"而不作答。**注意：跳过的答题通常不计分，个别平台
    可能判定为未完成任务点或不良行为**，请自行权衡（详见下文"自动下一节"）。
  - **隐藏登录提示遮罩**：有些网站会在切后台时弹出"一键登录 / 请登录"的浮层
    挡住画面，开启后自动隐藏这类浮层。
  - **调试日志**：排查用。打开后面板里显示拦截记录，页面左下角出现诊断浮层（见第五节）。
- 快捷键 **Alt+Shift+P** 全局切换开关（可在 `edge://extensions/shortcuts` 改键）。

### 自动下一节（怎么工作）

开启「下一节」后，扩展按超星任务点的真实结构跑一个**状态机轮询**（每 2 秒一次）：

0. **视频播到结尾 → 立即进入下一步**。这是**独立触发源**：
   判据是 `ended` 或 `currentTime >= duration - 1.2`，**不等平台标记、也不依赖调试浮层**
   （超星播放器有时停在最后一帧而不触发 `ended`，平台标记又要等它自己刷新）。播放器处于跨域 iframe 时，结束信号会通过 `postMessage` 交给顶层页面处理，因为外层无法直接读取 iframe 内的视频状态。
   按 `src|duration` 去重，同一个视频只推进一次。
1. **视频"在用"**（正在播放 / 可见且未播完 / 存在超星播放器 iframe），且当前不是可见的题目 iframe
   → **视频任务**：
   - 任务点已完成（`aria-label` 或 class `ans-job-finished`）→ 点"下一步"；
   - 任务点未完成 → 自动播放（静音）；
2. **可见的题目 iframe**（src 含 `api/work`，这是作业/测验任务的地址特征）
   → 直接点"跳过/下一步"，**不判断是否完成**；
3. 否则若从页面特征看**确实是题目页**（题目容器且有实际尺寸，或 ≥2 个题目特征词）→ 同样跳过；
4. 有视频元素/视频 iframe 但没在用 → **保守当视频任务**（宁可等，也不误跳）；
5. 完全没有视频（阅读等）→ 直接点"下一步"。

**自动播放是怎么保证成功的（v1.0.16 起）**：浏览器会拦截"带声音的自动播放"，所以扩展
在播放前**先把视频静音**（`pause()` → `muted = true` → `play()`，与成熟脚本一致），
并且**全程保持静音**——不再恢复声音；如果网站把视频解除静音，扩展会再按回静音。
这一步由**独立的「自动播放并保持」选项**驱动（默认开启，每 2 秒巡检一次），
**不需要开启「下一节」**，也不依赖任何其它组件。另外，**检测到题目弹题时不会抢播放**——
平台暂停视频就是为了让你答题。

**与"调试日志"的关系（v1.0.17 移除开关依赖，v1.0.18 补齐跨域帧转发）**：所有功能都**不读**调试日志开关，
关着浮层时行为与开着完全一致（测试里有专门的一致性用例）。
浮层只做显示，并且重绘被节流到最多 300ms 一次，尽量不扰动页面。
排查问题时**不需要开浮层**：面板里的「运行记录」始终可见，其中每 10 秒一条**心跳**会写明
`媒体数(播放/暂停/结束) | 任务类型 | 任务点 | 自动播放 | 下一节 | 日志浮层` 的状态。

> 超星的真实选择器（借鉴成熟脚本）：「下一章」按钮是 `.nextChapter` / `.jb_btn_92`
> （`#prevNextFocusNext` 用于判断是否最后一章）；任务完成标记是容器上的 class
> **`ans-job-finished`**（从视频 iframe 沿祖先链向上找，只判断当前视频任务）。

> 为什么要分两层判定：**只看"有没有 video 元素"会把题目页上的残留播放器当成视频页**；
> 而**只看"视频可见/在播"又会把还没渲染出来的真实视频页误判成题目页而跳过**。
> 所以用宽松的 `hasVideo()`（存在即算）+ 严格的 `videoActive()`（在用才算）配合，
> 并用 **iframe src（`api/work` = 题目）** 作为题目任务的权威判据；
> 只有"视频在用 且 当前不是可见的题目 iframe"才按视频任务处理。
> 检测会连同**子 iframe** 一起看（超星把播放器放在 iframe 里，父页面没有 `<video>`）；
> 播放器 iframe 按 URL（`ananas/modules/video`、`video-js`、`.m3u8`、`.mp4`）判断。
> 任务点完成判定只对**视频任务**生效，支持 `aria-label`（`任务点已完成`/`已完成`）
> 与 class **`ans-job-finished`**，不做可见性过滤（超星任务图标是 0×0 渲染）。
> "90%" 是平台自己的完成条件，扩展不感知它——只要标记变成"已完成"就推进。
> 找不到"下一步"时，运行记录里会**列出页面上可见的候选按钮**（文字 + class），
> 把它发我就能精确加上。

推进时按顺序尝试：播放器 API（`ananas.next`/`nextVideo`/`playNext`/`gotoNext`）→
答题"跳过/稍后/暂不"（**绝不替你作答**）→ 文字匹配"下一步/下一节/下一集/下一章/
下一课/下一个/继续学习"。两次点击之间至少间隔 2.5 秒，并过滤掉 `disabled` 的按钮。

**每一步都会写进"运行记录"**：检测到视频、任务点完成、无视频，以及具体点了哪个按钮/
调用了哪个 API、触发原因是什么，都能在面板里看到（状态变化只记一次，不刷屏）。

找不到可点击目标时会写一条日志，不会乱点。**限制与风险**：

- 各平台的按钮文字/结构不同，属于"尽力而为"；若你的平台按钮文字不在清单里，
  告诉我它显示的字样，我加到匹配表即可。
- 跳过答题意味着该任务点**不会被计为完成**；超星等平台对"未答题继续"可能记
  不良行为，请自行承担后果——这个选项默认关闭。

## 三、它是怎么做到的（七层防护）

网站暂停视频的手段基本只有四类，这个扩展逐层封堵：

| 层 | 网站的手段 | 扩展的应对 | 代码位置 |
|---|---|---|---|
| 1 | 读 `document.hidden` / `document.visibilityState` / `webkitHidden` 判断你是否离开 | 把这些属性改写成永远返回 `false` / `'visible'` | `injected.js` → `installVisibilitySpoof()` |
| 2 | 监听 `visibilitychange` / `blur` / `focusout` / `pagehide` / `freeze` 来暂停 | 页面注册这些监听直接被丢弃，这些事件也不再派发；`onXXX` 属性式监听同样失效 | `installEventBlockers()` |
| 3 | **监听 `mouseout` / `mouseleave` 判断"鼠标移出了播放器/窗口"** | 这些事件在捕获阶段就被丢弃（`blockMouseOut` 开关控制） | `installEventBlockers()` |
| 4 | 调用播放器自己的 API，例如超星的 `window.ananas.pause()` | 把 `ananas` / `ans` 上的暂停类方法换成守卫版本，并持续补刀晚挂载的播放器 | `installAnanasGuard()` |
| 5 | **查焦点**：`document.hasFocus()` 返回 false 就认为你离开了（典型写法是"鼠标移出 && 无焦点 → 暂停"） | `hasFocus()` 恒为 true、`activeElement` 不返回 null、`onblur` 失效 | `installFocusSpoof()` |
| 6 | 直接调用 `video.pause()`，或切后台时把你静音 | 包住 `pause()` 与 `muted`/`volume`：**只有用户亲手操作**时才放行，否则拒绝执行并立刻恢复播放 | `installPauseGuard()` / `installMuteGuard()` |
| 7 | 原生播放器绕过上面所有 JS 手段 | 监听 `pause` 事件 + 定时巡检，发现是网站暂停的就续播；用户刚点过鼠标/键盘的时间窗内不抢 | `startWatchdog()` |

### 第 5 层（焦点伪装）是怎么定位到的

用户反馈的一个现象是突破口：**"在页面空白处点右键弹出菜单后，再把鼠标移出页面，视频就不暂停了。"**

右键会让页面获得焦点（`document.hasFocus()` 变 true、`document.activeElement` 变得有效），
所以这说明超星的暂停条件里包含**焦点判断**，典型形式是
「鼠标移出/失焦事件 且 页面无焦点 → 调 `pause()`」。
只要让 `hasFocus()` 恒为 true，这整条判断就失效。

### 为什么"鼠标离开页面"是单独一层

**超星（学习通）并不靠 Page Visibility API 暂停视频，而是靠鼠标移出事件与播放器 API。**
它的播放器封装成 `window.ananas`，在捕获阶段监听 `mouseout` / `mouseleave`，鼠标一移出播放器或窗口就触发。

这一点有公开佐证：开源扩展 [NoStopVideo](https://github.com/BlairCode/NoStopVideo)（manifest 里写的就是 "Prevents videos from pausing on mouseout"）在实现说明里明确写道：
拦截捕获阶段的 `mouseout` 事件，并重写 `window.ananas.pause`。

### 实测依据

- 超星播放器页面 `/ananas/modules/video/index.html` 用的是 video.js 7.2.2 + 自研扩展；
  在其 `17_videojs-ext.min.js` 里，真正的 `pause()` 调用点只有"播放出错"和"本次学习时长已达上限"两类业务逻辑，
  **没有任何 `visibilitychange` / `document.hidden` 检测**——这说明它的防切屏不靠可见性 API。
- 播放器自带的脚本清单里也没有自研的焦点判断逻辑（`hasFocus`/`activeElement` 命中全部来自
  jQuery、video.js、echarts 三方库），因此焦点判断与暂停决策位于**需要登录的父页面**中，
  这也解释了为什么单靠拦截播放器内部事件不足以解决。
- 本项目的离线测试 `tests/smoke-test.js` 复刻了这些机制并逐条验证拦截效果。

### 关键实现细节

- 脚本通过内容脚本 `content.js` **同步注入**到页面主世界（不是隔离世界），并且运行时机是
  `document_start`，因此它改写的 `document.hidden` 就是页面自己 JS 读到的那一份。
  **注入的脚本文件必须在 `web_accessible_resources` 里声明**（v1.0.2 起已加），否则
  浏览器会拒绝加载，主世界什么都不会执行。
- 支持 `all_frames`，跨域 iframe 里的播放器同样被覆盖（很多网课平台把播放器放在 iframe 里）。
- 判断"是不是用户自己点的"用 `navigator.userActivation.isActive` 加上
  1.5～2.5 秒的用户手势时间窗，所以**你自己点暂停、拖进度条都正常**。
- 所有改写都包在 `try/catch` 里，任何一处失败都不影响网页本身。

## 四、本地验证（推荐动手做一次）

打开验证页 `tests/test-page.html`，这是一个**自包含的验证页**：视频由 canvas 实时生成，
不依赖网络；页面上完整复刻了超星的两套暂停机制（`mouseout`/失焦监听 +
`window.ananas.pause()` 调用，以及"移出且无焦点"的组合判定）。

**注意：不要用 file:// 双击打开**——扩展默认只注入 http/https 页面，file:// 下会显示"未运行"。
正确打开方式（任选其一）：

- 运行 `node tests/serve.js`，然后访问 `http://127.0.0.1:8123/`（推荐）；
- 或在 `edge://extensions/` 里给本扩展打开"允许访问文件 URL"，再双击打开该文件。

验证步骤：

1. 打开页面，先看顶部横幅：必须显示「✅ 扩展主世界脚本已运行 v1.0.3…」；
2. 点"播放"，画面开始走动、计时开始累加；
3. 鼠标移出浏览器窗口、切换标签页、最小化，等 10 秒以上；
4. 回到该页：**计时没有中断、画面一直在动**即说明生效。页面上的日志会记录每一次"暂停尝试"。

想对比效果，可以在 `edge://extensions/` 里临时关掉扩展，刷新本页再来一次——这时画面会立刻冻住。
页面顶部横幅显示的是主世界脚本的运行状态、版本号、组件清单和已阻止暂停次数，
它是验证注入是否成功的第一依据。

## 五、调试日志怎么开（排查时用）

**不需要打开开发者工具**，两种看法二选一：

1. **面板里看**：点扩展图标，下方"运行记录"**始终可见**——主世界脚本是否运行、
   注入失败原因、每次被拦截的暂停及调用来源都在这里。
2. **页面里看**：在"高级选项"里打开 **调试日志** 开关后，页面**左上角**会出现一个
   深色浮窗，显示：当前帧、已阻止多少次暂停、哪些组件安装成功，以及最近 200 条记录。
   **标题栏可按住拖动到任意位置**（`position:fixed`，不随页面滚动），
   右下侧有**滚动条**可回看历史记录（向上翻阅时不强制跳到底部）。
   浮窗只在顶层页面显示一个，不会在 iframe 里重复出现。

怎么判断问题出在哪：

- **先看面板顶部状态行**：v1.0.3 起它会显示「已生效 v…｜主世界已运行，保护了 N 个框架」。
  这个判定读的是主世界写进 DOM 的标记（两个世界共享 DOM，判定可靠）。
  如果显示"主世界未运行"，说明脚本没跑起来——重载扩展、F5，并看下方日志里的失败原因
  （常见：扩展没重载、`web_accessible_resources` 缺失、页面 CSP 拦截）。
- 浮层"已阻止暂停"的数字在增加，但视频仍然停 → 扩展拦到了某条路径，但还有别的路径，
  把记录里的调用来源发我即可继续定位。
- 数字一直是 0，而你看到视频暂停 → 暂停**没有走 JS 的 `pause()`**，大概率是 DRM/原生播放器，
  或者播放器被销毁重建（此时扩展会在"暂停守卫"之外靠巡检抢救）。
- 浮层完全没出现 → 注入没生效：看状态行是否"主世界未运行"，然后重载扩展 + F5。

> 调试日志默认关闭，只画一个可拖动的浮窗，不影响播放；排查完记得关掉。

## 六、环境要求与限制

- 需要 Chromium 内核 ≥ 102（Edge 102 发布于 2022 年，正常更新的电脑都满足）。
- **`edge://`、`chrome://`、扩展商店页面**等浏览器内置页面无法注入，属于浏览器
  安全限制，这些页面本来也没有视频。
- **关闭总开关后，已经打开的页面需要刷新一次**才会彻底失效（注入的补丁无法从
  已加载的页面中撤回）。反过来，从关到开也需要刷新。高级选项里的各项开关则可以
  立即生效，不用刷新。
- **第三方嵌入的播放器**（例如用 YouTube / Vimeo 嵌入的课程）依赖跨站 Cookie。
  如果浏览器把第三方 Cookie 拦了，切到后台时这类播放器可能自己停下来并显示
  "请登录 / 确认你不是机器人"，这属于浏览器的隐私机制，扩展无法代你登录。
  可以在浏览器设置里允许该站点的第三方 Cookie 缓解。
- 极少数使用 **EME/DRM 或原生直播播放器**（部分付费网课用 Widevine）的站点，
  暂停由浏览器原生模块控制，JS 层改不动，此时"巡检抢救"也救不回来。
- 浏览器在后台会把定时器降频到每分钟一次，所以"暂停事件监听"比定时器更关键，
  两者都已启用。
- 云桌面/远程桌面环境中，Windows 本身可能限制后台窗口渲染，这属于系统层面，
  与本扩展无关。

## 七、出问题怎么办（排查顺序）

1. **视频还是会暂停**
   - 先确认页面是安装扩展之后打开的：按 F5 刷新一次。
   - 打开面板确认总开关是绿的，并确认"拦截鼠标移出检测"也是开的。
   - **看面板顶部状态行**：必须显示"主世界已运行"。若显示"未运行"，先到
     `edge://extensions/` 点本扩展的**刷新按钮**，再 F5，然后看面板下方日志里的失败原因。
   - **打开"调试日志"，看左下角浮层和面板里的拦截记录**（见第五节），这是最快定位手段。
   - 打开 `edge://extensions/` → 本扩展 → 打开"错误"面板看有没有报错。
   - 到 `edge://extensions/shortcuts` 确认快捷键没被别的扩展占用（只影响快捷键）。
2. **我自己点暂停，它又自己播起来了**
   - 关掉"巡检抢救"。
   - 如果仍然如此，说明该站点的暂停不是由用户手势触发的（例如点了自定义按钮但
     用了 `setTimeout` 延迟暂停），把"阻止网站自动暂停"也关掉。
3. **某个网站的悬停菜单不灵了**
   - 关掉"拦截鼠标移出检测"（该项是给超星这类站点的，个别站点会受影响）。
4. **拖进度条后画面怪怪的**
   - 先关"巡检抢救"，因为它会在 1 秒内把暂停状态顶回去。
5. **某个网站行为异常（不只是视频）**
   - 在 `edge://extensions/` 里把扩展的"网站访问权限"改为"点击时"，
     或直接关闭总开关并刷新页面。
6. **想彻底卸载**：`edge://extensions/` → 移除。

## 八、文件结构

```
chaoxing-auto-extension/
├── manifest.json      # MV3 清单：权限、web_accessible_resources、内容脚本、快捷键、版本号
├── content.js         # 内容脚本（隔离世界）：同步注入主世界脚本、同步设置、中继诊断日志
├── injected.js        # 核心：跑在页面主世界，七层防暂停 + 自动下一节 + 诊断浮层
├── background.js      # Service Worker：快捷键切换开关、图标角标
├── popup.html/.js     # 工具栏面板（开关界面 + 运行记录）
├── icons/             # 16/32/48/128 图标
├── CHANGELOG.md       # 修改记录（以后所有删改都追加到这里）
├── SUMMARY.md         # 阶段性总结：各版本缺陷、根因与后续改正方向
└── tests/             # 验证工具（不属于扩展本体，可删除）
    ├── test-page.html       # 超星机制仿真验证页（用 serve.js 以 http 打开）
    ├── serve.js             # 本地静态服务器：node tests/serve.js → http://127.0.0.1:8123/
    ├── smoke-test.js        # 离线冒烟测试（Node）
    └── consistency-check.js # 配置/清单/诊断链路/CHANGELOG 一致性校验（Node）
```

跑一遍测试（可选，需 Node）：

```bash
node tests/smoke-test.js         # 结果：62 通过 / 0 失败
node tests/consistency-check.js  # 结果：一致性校验全部通过
```

`smoke-test.js` 用最小 DOM 替身验证了：可见性伪装生效、页面注册的
`visibilitychange`/`blur`/`mouseout`/`freeze` 监听被拦截、网站调用 `pause()` 被拒绝
而用户操作放行、`window.ananas.pause()` 被接管、静音守卫只在真实后台状态生效、
巡检能把暂停的视频续播。

`consistency-check.js` 校验四处默认配置、popup 控件、manifest 引用以及
**诊断链路（主世界记录 → 内容脚本中继 → 面板显示）**保持一致，防止改了开关却漏改某处。

## 九、隐私

扩展**不联网、不上传任何数据**，没有 `tabs`、`cookies`、`history` 等权限，
只在本地读取/写入你自己的开关设置（`chrome.storage.local`）。
权限说明：

- `storage`：保存你的开关设置。
- `scripting`：在页面里注入主世界脚本（核心功能）。
- `host_permissions: <all_urls>`：为了让所有网课站点都能生效。

全部代码都可以直接阅读，没有任何压缩或远程加载的脚本。
